SECTION 01

Executive Summary

Autonomous AI agents are rapidly becoming the dominant source of onchain transaction volume—executing high-frequency arbitrage, dynamic liquidity provision, automated collateral rebalancing, and per-token prompt inference payments. However, existing smart contract systems lack sub-second deterministic risk firewalls.

When an LLM agent prompt hallucinates or is hijacked via adversarial injection, it can drain an entire treasury within seconds. Multisigs introduce minutes of delay, destroying algorithmic profitability, while centralized offchain risk engines undermine self-custody.

The PulseGrid Breakthrough

PulseGrid provides an onchain deterministic risk firewall and high-throughput clearing mesh built natively for Monad. By evaluating spending ceilings, rolling velocity windows, and protocol allowlists across disjoint parallel storage slots, PulseGrid protects agent fleets at 10,000 TPS with 1-second single-slot finality.

SECTION 02

Protocol Architecture

PulseGrid is architected as three cleanly decoupled smart contracts on Monad:

PulseGridRegistry.sol

Maintains agent identities, operator addresses, treasury vaults, and risk tiers (Tier 1/2/3). Manages operational status transitions between Active and Quarantined.

PulseGridFirewall.sol

Pure deterministic policy engine. Validates single-tx spending caps, calculates rolling 1-hour velocity windows, enforces protocol allowlists, and houses emergency circuit breakers.

PulseGridClearing.sol

High-throughput settlement execution kernel. Dispatches verified calls to target protocols, implements nonReentrant state locks, and issues cryptographic receipts.

SECTION 05

Test Suite & Documented Failure Modes

The test suite executes 12 automated unit tests across all contracts. Each failure mode produces an explicit, machine-readable deterministic error code:

1. ERR_MAX_SINGLE_TX_EXCEEDED

Trigger: Agent Alpha (Tier 1 limit: 500 USDC) initiates execution of 1,200 USDC.
Handling: Intercepted prior to low-level target call. State is reverted and agent status is automatically set to Quarantined. Zero tokens leave the treasury.

2. ERR_TARGET_NOT_ALLOWLISTED

Trigger: Agent Beta initiates execution to unverified target address 0xHackerContract.
Handling: Firewall rejects call immediately. Destination code is never executed. Emits ActionQuarantined event.

3. ERR_HOURLY_VELOCITY_BREACHED

Trigger: Agent Alpha already spent 2,400 USDC in current rolling window and attempts additional 200 USDC (2,400 + 200 > 2,500 limit).
Handling: Velocity accumulator threshold triggers automatic halt. Protects against cumulative micro-draining.

4. ERR_GLOBAL_EMERGENCY_HALT

Trigger: Owner toggles emergencyHalt = true during unexpected upstream market volatility.
Handling: All agent executions across all tiers are immediately frozen fail-closed until emergency halt is revoked.

5. ERR_AGENT_NOT_ACTIVE

Trigger: Quarantined Agent attempts subsequent transactions.
Handling: Immediate rejection at step 1 of policy verification. Zero gas or state spent.

6. ERR_TARGET_CALL_REVERTED

Trigger: Downstream DEX pool reverts due to slippage.
Handling: Clearinghouse catches low-level revert gracefully, emits failed audit receipt, but does NOT debit spending velocity.

7. Reentrancy guard triggered

Trigger: Malicious destination contract attempts to call back into executeAction recursively.
Handling: Trapped by nonReentrant lock; transaction reverts completely.

SECTION 07

Why Monad Parallel EVM is Load-Bearing

On conventional EVM networks (Ethereum, Arbitrum, Base), executing high-frequency risk evaluations and clearing dozens of concurrent agent actions sequentially creates severe state lock contention and prohibitive gas costs ($15+ per check).

1. Disjoint Parallel State Execution

Because each agent's balance and velocity counters reside in disjoint storage slots, Monad's parallel execution engine processes multiple agent clearances simultaneously without lockups.

2. Single-Slot 1-Second Finality

When an adversarial anomaly is detected, quarantine state is finalized within 1 second across the entire network, preventing secondary attack transactions in consecutive slots.
